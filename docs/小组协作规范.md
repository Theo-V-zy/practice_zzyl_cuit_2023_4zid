# 小组协作规范

## 分支规则

- `main`：稳定主分支，只放已经能运行的代码。
- `feature/<姓名或模块名>`：个人开发分支，例如 `feature/zhangsan-nursing-item`。
- 合并方式：每个人开发完成后提交 Pull Request，由组长检查后合并。

## 每天开发流程

```bash
git checkout main
git pull
git checkout -b feature/你的模块名
```

开发完成后：

```bash
git add .
git commit -m "完成护理项目查询"
git push -u origin feature/你的模块名
```

## 提交要求

- 每次提交只做一类事情，例如“新增接口”“修复页面样式”“补充 SQL”。
- 提交前至少确认前端能打开、后端能启动。
- 改数据库结构时，同步修改 `database/zzyl.sql`，并在 PR 里说明。
- 不直接改别人的模块，确实需要改时先在群里说一声。

## 推荐分工

- 组员 A：用户登录、个人信息、修改密码。
- 组员 B：护理项目增删改查、图片上传。
- 组员 C：护理计划、计划项目关联。
- 组员 D：菜单布局、公共样式、接口联调和最终合并。
